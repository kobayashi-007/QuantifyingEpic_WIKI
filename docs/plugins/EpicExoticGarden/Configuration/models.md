# EpicExoticGarden 自定义模型数据（CustomModelData）配置教程

本教程将指导你如何为 **EpicExoticGarden（EEG）** 插件配置 `CustomModelData`，以便在 Minecraft 资源包（Resource Pack）中为植物、食材、料理和饮品显示精美的自定义材质。

---

## 一、 核心概念与准备工作

### 1. 什么是 CustomModelData？
`CustomModelData` 是 Minecraft 原生支持的一项功能（自 **1.14+** 版本引入）。它允许开发者在不添加全新物品 ID 的前提下，通过给同一种原版基础材质（如 `POTION`、`PLAYER_HEAD`、`OAK_SAPLING`）附加不同的数字标签，来实现千变万化的自定义外观。

### 2. 注意事项
* **服务器版本要求**：服务端与客户端必须在 **1.14 或更高版本**。
* **基础材质（Material）**：每个条目后面的 `# Material: ...` 注释说明了该物品在游戏内的原版底层载体。在制作资源包时，你需要针对这些基础材质编写对应的覆盖（Overrides）规则。
* **玩家头颅物品**：带有 `# Material: PLAYER_HEAD` 的物品，其“物品形态”的外观通常由皮肤数据决定，`CustomModelData` 主要用于控制其被放置为方块时的形态。
* **生效方式**：修改好配置文件后，在游戏内运行 `/eeg reload` 指令即可应用更改（注意：玩家背包里原有的物品可能不会实时刷新外观，需重新获取）。

---

## 二、 配置文件结构解析

配置文件按类别进行了清晰的划分：

```yaml
# =====================================================================
# 类别示例
# =====================================================================
ITEM_ID: 0  # Material: 对应原版基础材质
```

* **左侧 `ITEM_ID`**：插件内部定义的物品名称（例如 `GRAPE`、`BURRITO`）。
* **右侧数字**：你要赋予该物品的 `CustomModelData` 数值。
* **`0`**：代表使用默认的原版外观（不应用自定义模型）。
* **非 `0` 正整数**（如 `10040001`）：代表应用对应的自定义模型编号，资源包会根据这个编号检索材质。

---

## 三、 配置步骤

### 第一步：规划你的数字编号
为避免模型冲突，建议为不同的分类规划好数字区间。例如：
* **饮品类**：`10040001` ~ `10040050`
* **料理类**：`10050001` ~ `10050100`

### 第二步：修改配置文件
打开 `CustomModelData.yml`，将对应物品后面的 `0` 修改为你在资源包中分配的编号。例如：

```yaml
GRAPE_JUICE: 10040001  # Material: POTION
GRAPE_SMOOTHIE: 10040002  # Material: POTION
```

### 第三步：重载插件
保存文件后，回到游戏内输入：
```text
/eeg reload
```
看到配置重载成功的提示后，即可配合自制的资源包查看全新外观。

---

> 💡 **提示**：确保你的 Minecraft 资源包中的 `models/item/` 目录下，已经针对对应的基础材质（如 `potion.json`）配置好了 `predicate` 和 `custom_model_data` 匹配规则，这样材质才能正确显示！
